# TripTogether 用户研究计划 v2.0（基于痛点基线重构）

> 版本：v2.0 ｜ 制定人：用户体验研究员 ｜ 日期：2026-08-03
> 配套文档：《痛点基线合成.md》（二手研究假设，已完成）
> 研究目标：验证「朋友结伴出游」场景下的协作痛点假设（P1–P5），并为功能优先级排序提供量化依据
> 研究类型：三阶段混合方法 + **三方三角验证**（二手基线 → 定性 → 定量）

## 二、研究背景与起点

已完成输入：
- 《产品分析与实施计划》：15+ 竞品对比 + 市场结构分析
- **《痛点基线合成》：从二手研究提炼 5 条痛点假设（P1 信息碎片化 / P2 进度黑箱 / P3 参与门槛 / P4 Web 场景 / P5 迁移惯性），并标注置信度与待验证问题**
- MVP 已上线，8 大功能跑通

**核心判断**：二手基线证明"市场有空白、需求被竞品间接验证"，但**用户真实痛点尚未被直接观测**。本研究的科学价值，就在于用一手数据验证/推翻 P1–P5。

## 三、研究目标与决策问题

| 编号 | 目标 | 服务的决策 |
|------|------|------------|
| G1 | 验证/推翻 P1–P5 痛点假设（尤其 P2 进度黑箱、P4 Web 场景） | 决定核心卖点与平台形态（Web/App 资源配比） |
| G2 | 挖掘基线未覆盖的真实痛点（开放探索兜底） | 防止假设盲区，发现新机会 |
| G3 | 量化功能优先级，校准路线图 | V1.1 / V2.0 先做什么、砍什么 |

**决策问题**：朋友结伴出游人群中，P1–P5 哪些痛点真实且强烈？TripTogether 的进度看板 / 免注册协作 / Web 形态是否切中真需求？

## 四、基线痛点假设（摘要，详见《痛点基线合成》）

| 假设 | 陈述 | 置信度 | 验证紧迫度 |
|------|------|--------|------------|
| P1 | 规划信息散落群聊/Excel/地图/记账多工具 | 🟡 中 | 高 |
| P2 ⭐ | 规划进度黑箱（谁负责/完成没，看不见） | 🟠 低–中 | **最高** |
| P3 | 需下载App+注册劝退参与 | 🟡 中 | 高 |
| P4 ⭐ | "一起坐电脑前规划"适用 Web 优先 | 🔴 低 | **最高** |
| P5 | 微信群+Excel 的 DIY 惯性高，迁移难 | 🟡 中 | 中 |

## 五、研究方法与设计

```
二手基线《痛点合成》──┐
                     ├─▶ Phase 1 定性验证（8–10访谈+可选焦点组）
                     │     验证 P1–P5 / 挖掘新痛点
                     │            │
                     │            ▼
                     └─▶ Phase 2 定量验证（N=150–200问卷）
                            Kano + 痛点严重度 + 优先级
                                     │
                      三方三角验证：基线 ↔ 定性 ↔ 定量
                      冲突项必须标注并解释，不得单方面采信
```

| 阶段 | 方法 | 样本 | 产出 |
|------|------|------|------|
| 基线（已完成） | 二手研究合成 | 15+ 竞品 | P1–P5 假设 + 置信度 |
| Phase 1 | 假设验证型深度访谈 + 反证探针 | 8–10 人 | 假设验证矩阵、真实痛点地图、新发现 |
| Phase 1+ | 可选 焦点小组/协作工作坊 | 6–8 人 | 群体协作动态证据 |
| Phase 2 | 在线问卷（Kano + 严重度 + 优先级） | 150–200 | 功能优先级矩阵、痛点分布 |

**设计要点**：Phase 1 既"验证假设"也"开放探索"——每条假设都配**反证探针**（"有没有相反经历？"），避免确认偏误。

## 六、研究对象与招募

目标人群：**朋友结伴出游**
- 过去 12 个月 ≥2 人自主规划出游 ≥1 次
- 承担过组织者/半程组织者角色
- 年龄 22–35 为主，覆盖 18–45
- **特别配额**：至少 2–3 名"纯微信群+Excel DIY"用户（用于验证 P5 迁移惯性）

筛选题 + 配额（定性）：

| 维度 | 分层 | 人数 |
|------|------|------|
| 出行频率 | 高频(年≥4) / 低频(年1–3) | 各 4–5 |
| 角色 | 主导组织者 / 半程组织者 | 各 4–5 |
| 工具习惯 | 竞品App用户 / 纯DIY用户 | 混合，DIY≥2 |

招募渠道：朋友圈/社群定向 + 小额激励（访谈 ¥80–120，问卷抽奖）。保留原生"微信群规划"用户以捕捉真实痛点。

## 八、Phase 1 假设验证型访谈

### 8.1 访谈提纲（约 55 分钟）

**A. 暖场与真实出行回顾（开放）**
1. 最近一次和朋友出游？去哪？几个人？谁发起？
2. 用三个词形容"做计划"的过程。

**B. 规划旅程回顾（行为，非假设）**
3. 从"想去"到"出发"经历哪些步骤？在哪沟通？
4. 你们用了哪些工具（群聊/文档/备忘录/App）？各自干嘛？
5. 有没有信息分散、有人不知道最新安排、重复劳动、冲突？**具体一次。**

**C. 假设探针（逐条 P1–P5）**
- **P1 碎片**："规划信息分散在好几个地方，这让你困扰过吗？举例。"
- **P2 进度黑箱**："你们怎么知道'谁负责什么、办没办妥'？有没有过'以为定了其实没定'？"
- **P3 门槛**："有没有为朋友下载/注册过某个规划App？体验如何？"
- **P4 场景**："你们是各自手机弄，还是凑一起用电脑弄？多人同时改一份计划多吗？"
- **P5 惯性**："现在微信群+Excel 够用吗？什么情况下你会想换工具？"

**D. 反证探针（防确认偏误，每条假设后追问）**
- "有没有相反的情况？比如信息分散反而没给你造成麻烦？"
- "如果有个工具能解决 X，但要多一步操作，你还会用吗？"

**E. 概念探针（对 MVP 功能直觉）**
9. 能看到同伴负责事项完成状态的面板，有用吗？为什么？
10. 不用注册就能看行程链接，vs 必须注册，你倾向哪个？
11. 每天地点在地图连成线，有吸引力吗？

**F. 收尾**
12. 什么情况下你会从微信群切换到专门工具？

### 8.2 假设验证矩阵（分析用）
每个受访者对 P1–P5 标记：✅ 强烈印证 / ◐ 部分印证 / ❌ 推翻 / ➖ 未触发。汇总得假设验证率。

## 九、Phase 2 定量（基于基线功能池）

问卷结构：筛选题 → 行为题 → **痛点严重度**（P1–P5 典型场景 5 点李克特）→ **Kano 功能评估** → **优先级排序** → 人口统计。

**Kano 功能池（由 P1–P5 派生）**：
| 功能 | 对应假设 | 正向题 | 反向题 |
|------|----------|--------|--------|
| 统一计划载体（看板/日程/交通/住宿/费用合一） | P1 | 有则？ | 无则？ |
| 进度看板（状态+负责人+完成率） | P2 | 有则？ | 无则？ |
| 免注册邀请链接 | P3 | 有则？ | 无则？ |
| Web 优先（电脑大屏协作） | P4 | 有则？ | 无则？ |
| 极简上手（无需学习） | P5 | 有则？ | 无则？ |
| 地图路线总览 | — | 有则？ | 无则？ |
| AA 自动分账 | — | 有则？ | 无则？ |

Kano 分类（M/O/A/I/R）+ CS/DS 系数 + 优先级二维矩阵，方法同 v1。

## 十、数据分析与三方三角验证

### 10.1 定性（主题分析）
转写 → 编码 → 亲和图 → 痛点主题；输出**假设验证矩阵**与**真实痛点地图**。

### 10.2 定量（Kano + 统计）
清洗 → 逐功能 Kano 分类 → CS/DS → 优先级矩阵 → 按角色/频率交叉分析 → 痛点严重度与功能价值相关性。

### 10.3 三方三角验证（核心）
| 冲突情形 | 处理规则 |
|----------|----------|
| 基线说有痛点，定性未发现 | 怀疑样本偏差或场景不对，Phase 2 加大该假设样本 |
| 定性强烈，定量低分 | 标注"样本偏差风险"，不盲目排期 |
| 定量高分但基线未提 | 新机会，进入路线图候选 |
| 三方一致 | 高置信度结论，直接支撑决策 |

## 十二、质量保障与伦理
- 知情同意、数据匿名、激励不影响作答
