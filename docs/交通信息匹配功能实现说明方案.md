# 交通信息匹配（Traffic Info Matching）功能实现说明方案

> 文档版本：v1.0
> 适用项目：TripTogether（多人协作旅游规划平台，Web 优先）
> 编写日期：2026-08-12

---

## 0. 方案依据说明（重要）

本方案依据此前对话「搜索一些 skill」中检索到的地图类 Skill 能力撰写。由于对话索引未能直接回放该历史对话原文，本方案以**对话所检索到的、与交通匹配直接相关的两个 Skill 的真实能力**为准进行落地设计（已在本会话内加载确认）：

1. **腾讯地图·地图助手 Skill（`tencentmap-map-assistant`）** —— 核心能力来源
   - 路线规划 `direction`：驾车 / 步行 / 公交 / 骑行
   - 两点距离 `distance_matrix`：距离 + 用时
   - 地址解析 `geocoder` / 逆解析 `regeocoder`、关键词提示 `poi_sug` / `poi_search`
   - 坐标系转换 `coord_translate`：GPS(WGS-84) → GCJ-02（腾讯地图坐标系）
   - 行程 / 多 POI 可视化（基于腾讯地图 JSAPI GL）
2. **地图合规守卫 Skill（`geo-map-compliance-guard`）** —— 强制合规约束
   - 仅允许腾讯 / 高德 / 百度 / 天地图；默认腾讯；坐标系 GCJ-02
   - 前端密钥不可硬编码可用 Key；生产环境需后端代理或 Referer 白名单
   - 中国区域地图展示须符合国界、南海诸岛等国家标准

## 1. 背景与目标

### 1.1 现状（来自代码现状）
- `server/src/entities/ScheduleItem.ts`：`transportToNext` 字段为 **`varchar` 自由文本**，目前由用户手动填写（如「打车 10 分钟」），无距离 / 时长 / 路线坐标等结构化信息。
- `server/src/entities/Transportation.ts`：已存在城际交通实体（type: `departure|return|intercity`，transportType: `flight|train|bus|car|ship|other`），但起终点 `departurePlace/arrivalPlace` 也是自由文本，未与行程 POI 关联。
- `client/src/utils/tencentMap.ts`：已实现 `getCachedRoadPath()` —— 调用 `TMap.service.Direction` 做 WALKING / DRIVING 路线规划，自带内存 + localStorage 缓存（30 天 TTL、800 条上限）、瞬时/持久错误分类与指数退避重试、失败直线兜底。**这是匹配引擎可直接复用的底座。**
- 坐标系：项目约定统一使用 **GCJ-02**（与腾讯地图一致，无需转换）。

### 1.2 目标
把「行程接驳交通」从「人工自由文本」升级为「系统自动匹配 + 结构化落库 + 地图可视化」：
1. **市内接驳**：自动匹配相邻 POI 之间的步行 / 驾车 / 公交接驳，给出距离、时长、真实路线 polyline。
2. **城际交通**：识别跨城市 / 跨天行程段，自动建议交通方式（飞机 / 高铁 / 大巴 / 自驾）并生成 `Transportation` 草稿，等待用户确认。
3. **地图总览**：复用现有地图，把匹配出的每段路线按交通方式着色渲染。

### 1.3 非目标（本期不做，列入 V2）
- 实时票价 / 余票查询与第三方预订闭环
- 多方案并排对比 UI、用户自定义偏好（如「只坐高铁」）
- 实时路况动态刷新（本期用规划结果静态落库）

## 3. 数据模型设计

### 3.1 ScheduleItem 扩展（市内接驳）
保留 `transportToNext` 作为「人工备注 / 覆盖说明」，新增结构化接驳字段：

```typescript
// server/src/entities/ScheduleItem.ts 追加
@Column({ type: "varchar", nullable: true })
legMode: "walking" | "driving" | "transit" | "intercity" | "none" | null;

@Column({ type: "float", nullable: true })
legDistanceM: number;        // 接驳距离（米）

@Column({ type: "float", nullable: true })
legDurationMin: number;      // 接驳时长（分钟）

@Column({ type: "text", nullable: true })
legPolyline: string;         // GCJ-02 坐标点 JSON：[{lat,lng},...]

@Column({ type: "varchar", nullable: true })
legSummary: string;          // 展示文案，如「驾车约 12 分钟 · 3.2 km」

@Column({ type: "boolean", default: false })
legAutoMatched: boolean;     // 是否系统自动匹配（区别于人工填写）
```

> 前端 `client/src/types/index.ts` 的 `ScheduleItem` 同步增加对应可选字段。

### 3.2 Transportation 增强（城际草稿）
```typescript
// server/src/entities/Transportation.ts 追加
@Column({ type: "float", nullable: true })
distanceM: number;

@Column({ type: "float", nullable: true })
durationMin: number;

@Column({ type: "text", nullable: true })
polyline: string;            // GCJ-02 坐标点 JSON

@Column({ type: "varchar", nullable: true })
fromItemId: string;          // 关联起点 ScheduleItem

@Column({ type: "varchar", nullable: true })
toItemId: string;            // 关联终点 ScheduleItem

@Column({ type: "boolean", default: true })
matched: boolean;            // true=系统建议，待用户确认
```

### 3.3 迁移脚本
- 新增字段均为 `nullable`，向后兼容，无需回填历史数据。
- 历史 `transportToNext` 文本保留，作为 `legSummary` 的初值（若 `legMode` 为空）。

## 4. 匹配引擎设计（核心）

### 4.1 输入
按 `dayIndex` + `sortOrder` 排序的 `ScheduleItem` 序列（需含 `lat/lng`）。缺坐标的 item 先用 `geocoder`（`policy=1` 宽松策略，支持景点名）补坐标。

### 4.2 分段规则
| 段类型 | 判定 | 处理方式 |
|--------|------|----------|
| 市内接驳 | 同日相邻 item，且起终点城市相同 | `direction` + `distance_matrix` |
| 城际交通 | 跨城市，或跨天「当日终点 → 次日起点」 | 生成 `Transportation` 草稿 |
| 无坐标 | item 缺 `lat/lng` | 跳过该段，标记 `legMode=null` |

> 城市判定：复用现有 `Trip.destination` 或首个有坐标 item 的 `regeocoder` 反查城市；城际以「直线距离 > 100 km」为强信号。

### 4.3 市内接驳匹配
- 距离 < 1 km → `walking`；否则 `driving`（与现有 `getCachedRoadPath` 阈值一致）。
- 调用链：**复用 `getCachedRoadPath(TMap, a, b)`**（已含缓存、重试、失败直线兜底）。
- 额外用 `distance_matrix` 取精确 `distanceM` / `durationMin`，写入 `legDistanceM` / `legDurationMin` / `legSummary`。
- `legMode=transit` 场景（用户偏好公交）：改调 `direction(mode="transit")`，从返回方案里取首条。

### 4.4 城际交通建议
1. `geocoder` 标准化起终点 → `distance_matrix` 估算直线距离。
2. 按距离阈值建议 `transportType`（可配置）：
   - `< 300 km` → 高铁 / 自驾优先（`train` / `car`）
   - `300–800 km` → 飞机 / 高铁（`flight` / `train`）
   - `> 800 km` → 飞机（`flight`）
3. 生成 `Transportation` 草稿：`type="intercity"`、`status="pending"`、`matched=true`、**不自动确认**。
4. 写入 `fromItemId` / `toItemId`，便于地图回溯与用户确认后联动。

### 4.5 坐标系与兜底
- 项目坐标已约定 GCJ-02，**无需转换**。
- 若支持外部导入 GPS（WGS-84），先 `coord_translate(type=1)` 转 GCJ-02 再入参（见 Skill 要点 7）。
- 路线规划失败：复用现有 `isTransientError` 分类 —— 瞬时错误下次刷新重试，持久错误（配额/鉴权）直线兜底并缓存，避免反复打 API。

## 5. 接口设计

### 5.1 后端（server）
| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `POST` | `/api/trips/:tripId/match-transport` | 触发全量匹配，返回 matched legs + 城际草稿 | `requireTripMember` |
| `GET` | `/api/trips/:tripId/transport-legs` | 查询匹配结果（市内 + 城际） | `requireTripMember` |
| `PATCH` | `/api/schedule-items/:id/transport` | 人工修正某段（覆盖 `legMode` 等，`legAutoMatched=false`） | `requireTripMember` |
| `PATCH` | `/api/transportations/:id/confirm` | 确认 / 修改城际草稿（`matched=false`, `status` 流转） | `requireTripMember` |

> 权限沿用现有三级链（`authenticate → requireTripMember → requireTripOwner`），分享只读链接 `/api/trips/share/:inviteCode` 不暴露匹配写接口。

### 5.2 前端（client）
- 新增 `useTransportMatch` hook：封装匹配触发与结果读取。
- `TripDetail.tsx`：新增「一键匹配交通」按钮；`transportToNext` 展示区改为**结构化接驳卡片**（方式图标 + 距离 + 时长 + 「修改」入口）。
- `MapView.tsx`：渲染匹配路线，按 `legMode` 着色 —— walking 绿、driving 蓝、transit 橙、intercity 紫（复用现有按天分色 Marker + 真实路径连线逻辑）。
- 城际草稿在「交通」面板以待确认列表呈现，确认后进入 `Transportation` 正式列表。

## 6. 地图可视化（复用 + 合规）

- **底图**：复用现有 `TENCENT_MAP_KEY` + 腾讯地图 JSAPI GL（`libraries=service`）。
- **路线**：用 `direction` 返回的真实 polyline 渲染；失败直线兜底（已有）。
- **合规红线**（来自 `geo-map-compliance-guard`）：
  - 仅用腾讯地图底图，坐标系 GCJ-02，**不得混用 Google / OSM / Mapbox 等境外服务**。
  - 不渲染军事禁区、未公开敏感坐标；国界 / 南海诸岛须符合国家标准。
  - 个人打卡坐标仅本地私有存储，不公开他人位置（《个人信息保护法》）。
- **密钥安全**（既有风险，本期提示、V2 治理）：
  - 当前 `tencentMap.ts` 已在**前端硬编码 Key**（`5ULBZ-...`），属既有模式。
  - 合规要求：个人用途配置 **Referer 域名白名单**；商业用途必须**后端代理** Key，前端不留可用 Key。
  - 建议 V2 将 Key 移入后端代理（参考 `geo-map-compliance-guard` 的 `_TMapSecurityConfig` 代理模式），前端按默认场景走代理、不出现明文 Key。

### 7.2 匹配引擎伪代码
```typescript
async function matchTransport(items: ScheduleItem[]): Promise<MatchResult> {
  const sorted = sortByDayThenOrder(items);
  const legs: Leg[] = [];
  const intercity: Transportation[] = [];

  for (let i = 0; i < sorted.length - 1; i++) {
    const a = sorted[i], b = sorted[i + 1];
    if (!a.lat || !b.lat) continue;                 // 无坐标跳过
    const dist = haversine(a, b);
    if (dist > INTERCITY_THRESHOLD_KM * 1000) {     // 城际
      const t = await suggestIntercity(a, b);       // geocoder + distance_matrix + 阈值
      intercity.push(t);
    } else {                                        // 市内接驳
      const poly = await getCachedRoadPath(TMap, a, b); // 复用现有底座
      const dm = await distanceMatrix(a, b);
      legs.push({ fromId: a.id, toId: b.id, mode: dist < 1000 ? "walking" : "driving",
                  distanceM: dm.distance, durationMin: dm.duration, polyline: poly, autoMatched: true });
    }
  }
  return { legs, intercity };
}
```

## 8. 风险与注意事项

| 风险 | 等级 | 缓解 |
|------|------|------|
| 路线规划为付费 WebService，超额配额 | 🟡 | 复用缓存（30 天 / 800 条）+ 失败直线兜底；P5 监控配额 |
| 前端硬编码 Key 泄露 | 🟡 | 本期提示；V2 后端代理 / Referer 白名单（合规要求） |
| 坐标系不一致导致偏移 | 💭 | 强制 GCJ-02；外部 GPS 先 `coord_translate(type=1)` |
| 匹配结果不准（如误判城际） | 💭 | 结果均为「建议 + 待确认」，用户可覆盖；阈值可配置 |
| 合规越界（误用境外地图） | 🔴 | 仅腾讯底图 + GCJ-02，遵守国界 / 敏感区红线 |

## 9. 验收标准（Definition of Done）

- [ ] 触发「一键匹配」后，同城相邻 POI 自动填充 `legMode / legDistanceM / legDurationMin / legPolyline / legSummary`。
- [ ] 跨城市段自动生成 `Transportation` 草稿（status=pending, matched=true），地图按色渲染。
- [ ] 地图总览正确显示各段路线，失败段直线兜底且不报错。
- [ ] 用户可人工修改任一段，修改后 `legAutoMatched=false` 且不被自动覆盖。
- [ ] 全程仅使用腾讯地图底图与 GCJ-02 坐标系，无任何境外地图依赖。
- [ ] 单测覆盖分段 / 阈值 / 兜底逻辑；配额相关调用有缓存与降级。
