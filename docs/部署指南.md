# TripTogether 部署指南

> 适用环境：腾讯云 Lighthouse（OpenCloudOS，2C2G/40GB，公网 IP 49.232.53.191）
>
> 部署架构与 free-memory 同构：**前端静态文件由 nginx 托管 + 后端 Express 由 pm2 守护 + nginx 反代 /api + PostgreSQL 本机复用**

---

## 一、部署架构与端口规划

### 1.1 服务器现状（已占用端口）

| 端口 | 用途 | 归属 |
|---|---|---|
| 80 | free-memory 旧 UI 正式版 | /opt/free-memory |
| 8080 | free-memory 新 UI（island） | /opt/island |
| 4000 | free-memory 共享 Express 后端 | - |
| 5432 | PostgreSQL（本机，仅监听 127.0.0.1） | 已安装，**复用，不重装** |

### 1.2 TripTogether 新增占用

| 端口 | 用途 | 监听范围 |
|---|---|---|
| **8081** | nginx 托管前端静态文件 | 0.0.0.0（安全组放行） |
| **3001** | Express 后端 | 127.0.0.1 走本机反代，**不对公网暴露** |
| 5432 | 复用现有 PostgreSQL，新建独立库 `trip_together` | 不变 |

### 1.3 关键前提

- 前端 `client/src/api/client.ts` 已写死 `baseURL: "/api"` 相对路径 → **前端代码零改动**，只需 nginx 反代。
- 后端 `server/src/index.ts` 从 `PORT` 环境变量读端口，默认 3001。
- 代码通过 GitHub 中转到服务器（本机沙箱 git 写操作被封，push 须在自有终端执行）。

## 二、服务器环境检查与准备

```bash
# 1. 确认 PostgreSQL 已在跑（free-memory 在用，应输出 active）
systemctl status postgresql

# 2. 确认 pm2 是否已装；没有就装
pm2 -v || sudo npm install -g pm2

# 3. 确认 Node 版本 >= 18（TypeScript 5.5 + TypeORM 0.3 要求）
node -v

# 4. 确认 3001 / 8081 端口空闲
ss -tlnp | grep -E ':3001|:8081'
# 无输出即可用
```

## 三、数据库准备（复用现有 PostgreSQL 实例）

```bash
sudo -u postgres psql
```

在 psql 中执行（**为 TripTogether 建独立用户和库，与 free-memory 数据隔离**）：

```sql
CREATE USER trip_user WITH PASSWORD '替换为强密码';
CREATE DATABASE trip_together OWNER trip_user;
GRANT ALL PRIVILEGES ON DATABASE trip_together TO trip_user;
\q
```

> 注意：不要动 free-memory 已有的数据库和用户。PostgreSQL 保持仅本机监听（`pg_hba.conf` 默认），安全组不放行 5432。

## 四、后端部署

### 4.1 拉代码

```bash
# 本机（Windows CMD）先推送到 GitHub —— 沙箱限制，须在自有终端执行
# git add . && git commit -m "..." && git push

# 服务器上
sudo mkdir -p /opt/triptogether && sudo chown $USER /opt/triptogether
cd /opt/triptogether
git clone <你的仓库地址> .
```

### 4.2 安装依赖并配置环境变量

```bash
cd /opt/triptogether/server
npm install
cp .env.example .env
vi .env
```

`.env` 生产配置（逐项确认）：

```ini
# 数据库（本机复用现有 PG）
DB_HOST=localhost
DB_PORT=5432
DB_USERNAME=trip_user
DB_PASSWORD=第三节设置的真实密码
DB_NAME=trip_together

# 首次部署 true 自动建表；表结构稳定后改为 false
DB_SYNCHRONIZE=true

# 服务端口
PORT=3001

# JWT：生产环境必须用新随机值，不要复用开发环境的
# 生成命令：openssl rand -hex 32
JWT_SECRET=粘贴 openssl rand -hex 32 的输出
JWT_EXPIRES_IN=7d

# 航班查询 Key（可选，不配则回退 mock 数据）
AVIATIONSTACK_KEY=
```

### 4.3 编译 + pm2 启动

```bash
npm run build          # tsc 编译到 dist/
pm2 start dist/index.js --name triptogether-api
pm2 save               # 保存进程列表
pm2 startup            # 按提示再执行一条 sudo 命令，实现开机自启
```

> 2C2G 内存有限，建议给进程加内存上限自动重启：
>
> `pm2 start dist/index.js --name triptogether-api --max-memory-restart 400M`

验证：

```bash
curl http://127.0.0.1:3001/api/health
# 期望返回 {"status":"ok","time":"..."}
pm2 logs triptogether-api --lines 20   # 应看到 "数据库已连接"
```

## 六、nginx 配置

新建 `/etc/nginx/conf.d/triptogether.conf`：

```nginx
server {
    listen 8081;
    server_name 49.232.53.191;

    # 前端静态文件
    root /opt/triptogether/client-dist;
    index index.html;

    # SPA 路由回退（/share/:inviteCode 等前端路由必需）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反代到后端（3001 仅本机可达）
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

> 不要改动 free-memory / island 已有的 nginx 配置文件，新站独立 conf 互不影响。

## 七、安全组与地图 Key

1. **腾讯云控制台 → Lighthouse 防火墙**：放行 TCP **8081**。
   - 3001（后端）和 5432（数据库）**不要放行**，均走本机回环。
2. **腾讯地图控制台**：key 的 Referer 白名单增加 `49.232.53.191:8081`（按域名/IP 白名单格式填写），否则地图可能被 key 防盗链拦截。


## 十、注意事项与已知取舍

1. **`DB_SYNCHRONIZE`**：MVP 阶段保持 `true` 方便迭代；表结构稳定后改 `false`，避免重启时 schema 漂移风险（项目尚未引入 migration 脚本）。
2. **`/api/trips/share/:inviteCode`** 为公开只读端点（零门槛协作特性），无 JWT 保护，属设计预期。
3. **`.env` 不入库**：已由 `.gitignore` 忽略，服务器上手工维护；换服务器时需手动迁移。
4. **2C2G 资源紧张**：TripTogether 后端已加 `--max-memory-restart 400M`；若整体内存吃紧，优先观察 `free -h` 与 `pm2 monit`。
5. **HTTPS**：当前 IP 直连无证书；后续绑域名后可用 certbot 免费签发，nginx 加 443 监听即可，架构不用变。
