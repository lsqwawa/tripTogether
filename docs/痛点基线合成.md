# TripTogether 痛点基线合成（二手研究）

> 版本：v1.0 ｜ 制定人：用户体验研究员 ｜ 日期：2026-08-03
> 来源：《产品分析与实施计划》（15+ 竞品对比 + 市场结构分析）
> 性质：**基线假设（baseline hypotheses）**，非一手验证结论

---

## 0. 方法论说明与重要局限

本基线从既有二手研究中提取"用户痛点信号"，结构化为**可证伪的痛点假设**，作为后续一手用户研究的验证靶标。

**证据来源**：15+ 竞品功能对比表、市场结构判断、团队对"用户习惯"的推断。

**⚠️ 关键局限（必须正视）**：本基线并非来自直接用户观察或访谈，而是从"竞品功能缺口"反推"用户痛点"。这种推理存在**生态谬误风险**——竞品没做 ≠ 用户需要。因此本基线所有结论的置信度均标记为「待一手验证」，不得作为产品决策的终据。研究计划 v2.0 中 Phase 1/2 的全部设计，目的就是验证或推翻这些假设。

| 编号 | 原始陈述 | 出处 |
|------|----------|------|

## 2. 基线痛点假设（P1–P5）

每条含：陈述、证据、推断逻辑、**待验证关键问题**、功能机会、置信度。

### P1 信息载体碎片化
- **陈述**：朋友结伴出游时，规划信息散落在群聊/Excel/地图/记账等多个工具，缺乏统一载体，导致信息不同步、查找难。
- **证据**：S1、S2
- **推断**：多工具切换 = 协作摩擦。但"用户是否真的感到痛"未知——很多人可能觉得微信群够用。
- **待验证**：实际用几个工具？切换频率？是否因此出过错（订重/漏订/信息冲突）？
- **功能机会**：统一计划载体（进度看板+日程+交通+住宿+费用合一）
- **置信度**：🟡 中（市场结构支持，缺直接证据）

### P2 规划进度黑箱 ⭐核心差异化假设
- **陈述**：多人规划时，谁负责什么、完成到哪了，其他人看不到，导致重复劳动/遗漏/焦虑。
- **证据**：S3、S7
- **推断**：进度不可见 = 协作不确定性。这是 TripTogether 最大差异化，但也最是"我们推测"出来的点。
- **待验证**：是否经历过"以为别人订了其实没订"？频率？情绪强度？没有进度追踪时怎么弥补？
- **功能机会**：进度看板（环节状态标记 + 负责人 + 整体完成率）
- **置信度**：🟠 低–中（差异化最强，最需验证）

### P3 协作参与门槛高
- **陈述**：需下载 App + 注册的协作工具，会劝退部分旅伴参与。
- **证据**：S6、3.3
- **推断**：低门槛 = 高参与。但需验证"免注册查看"是否真提升参与，还是用户根本不在乎注册。
- **待验证**：是否为旅伴注册过 App？体验如何？免注册链接会提高分享意愿吗？
- **功能机会**：邀请链接免注册查看/编辑
- **置信度**：🟡 中

### P4 Web 端协作场景假设 ⭐影响平台形态决策
- **陈述**：对于"一起坐在电脑前规划"的场景，App 优先的产品体验不佳，Web 优先是差异机会。
- **证据**：S4
- **推断**：场景假设——"一起坐电脑前规划"是否常见？年轻朋友结伴可能更倾向手机。
- **待验证**："共同规划"发生在什么设备？手机还是电脑？多人同时在线编辑需求多大？
- **功能机会**：Web 优先产品形态
- **置信度**：🔴 低（场景假设存疑，需验证）

### P5 迁移成本 / DIY 惯性
- **陈述**：用户习惯微信群+Excel，新产品需明显优于 DIY 才能促迁移。
- **证据**：S5、七·风险评估
- **推断**：这是 adoption 门槛假设。
- **待验证**：现有 DIY 方案的真实痛点强度？什么触发点会让他们换工具？
- **功能机会**：极简上手 + 明显价值闭环
- **置信度**：🟡 中（迁移难是常识，但"多明显才够"未知）

## 3. 功能机会映射表

| 痛点假设 | 对应 TripTogether 功能 | 验证优先级 |
|----------|------------------------|------------|
| P1 信息碎片化 | 统一计划载体（看板/日程/交通/住宿/费用合一） | 高 |
| P2 进度黑箱 | 进度看板（状态+负责人+完成率） | **最高** |
| P3 参与门槛 | 免注册邀请链接（只读/编辑） | 高 |
| P4 Web 场景 | Web 优先形态 | **高（影响形态）** |
| P5 迁移惯性 | 极简上手引导 + 价值闭环 | 中 |

## 4. 置信度总览与验证排序

| 假设 | 置信度 | 验证紧迫度 | 原因 |
|------|--------|------------|------|
| P2 进度黑箱 | 低–中 | **最高** | 核心卖点，错则方向偏 |
| P4 Web 场景 | 低 | **最高** | 决定 Web/App 资源投入 |
| P1 信息碎片化 | 中 | 高 | 功能架构基础 |
| P3 参与门槛 | 中 | 高 | 协作冷启动关键 |
| P5 迁移惯性 | 中 | 中 | 影响增长策略 |

---

## 5. 对研究计划的影响

1. **Phase 1 定性访谈**：由"开放探索"转为**假设验证型**——提纲加入对 P1–P5 的定向探针，但保留开放探索空间（防止假设本身错误）。
2. **Phase 2 定量问卷**：基于 P1–P5 派生功能池，做 Kano + 优先级排序。
3. **三方三角验证**：基线（二手）→ 定性（一手）→ 定量（一手）。任两方冲突，必须标注并在报告中解释，不得单方面采信。
